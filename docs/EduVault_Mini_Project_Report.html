1. INTRODUCTION

1.1 Existing System, Proposed System and Need and Objective of System

Existing System: Traditional academic credential management in higher education institutes heavily depends on physical paper documents or unauthenticated PDF files. In this manual model, students submit physical photocopies for placement eligibility and administrative checks. Academic verification committees manually inspect and stamp records, leading to severe administrative overhead, multi-week delays for corporate background checks, and an inherent vulnerability to resume fraud and document alteration.

Proposed System (EduVault): EduVault is an enterprise-grade Digital Locker and Academic Credential Verification platform. It provides a secure, role-governed ecosystem supporting four primary user roles: Student, Alumni, Academic Committee, and Placement Team. Students securely upload marksheets, certificates, internships, and technical projects. The Academic Committee reviews and verifies credentials in real-time. Placement officers leverage verified student dossiers with dynamic CGPA and departmental filtering. Every candidate receives a cryptographic Interview Key that compiles into an instant QR Code for on-the-spot mobile verification by recruiters.

Need of the System: There is a critical institutional need to eradicate academic fraud, streamline campus placement drives, and offer students lifelong cloud-native access to authenticated academic credentials. EduVault provides an immutable, transparent single source of truth for students, recruiters, and administrators.

Objectives of the System:

  • Implement a high-speed, secure RESTful API using Django REST Framework and PostgreSQL.
  • Deliver an intuitive, responsive frontend using React 18, Vite, and Tailwind CSS.
  • Establish strict Role-Based Access Control (RBAC) across 4 roles.
  • Integrate dynamic QR Code generation for instant physical and digital interview verification.
  • Deploy the entire full-stack platform to 100% free production cloud tiers (Vercel, Render, and Neon).

1.2 Scope of Work

The scope of EduVault covers user authentication with JWT, digital document storage with MIME-type and size validators, an academic committee approval/rejection pipeline with candidate feedback, a placement candidate discovery portal, a dynamic alumni directory with mentorship status, and public endpoints for QR-based dossier verification.

1.3 Operating Environment – Hardware and Software

Hardware Requirements: Dual-core 2.0 GHz processor or higher, 8 GB RAM (16 GB recommended), 500 MB storage. Compatible with standard desktop browsers and modern Android/iOS mobile cameras.

Software Requirements: Windows 11 / Ubuntu 22.04 LTS, Python 3.11, Node.js v20, Django 6.0, Django REST Framework, React 18, Vite, PostgreSQL 16 (Neon Serverless), WhiteNoise, and Gunicorn.

1.4 Description of Technology Used

React 18 & Vite: High-performance reactive UI rendering with instantaneous hot module reloading and fast client bundle compilation.

Tailwind CSS: Modern utility-first CSS styling enabling responsive layouts, micro-animations, and clean typography without heavy style dependencies.

Django & Django REST Framework: Robust Python backend framework providing built-in ORM security against SQL injections, CSRF protection, and high-throughput serialization.

Neon PostgreSQL 16: Cloud-native serverless PostgreSQL providing full ACID compliance, foreign key integrity, and zero-maintenance storage.

2. PROPOSED SYSTEM

2.1 Feasibility Study

Operational Feasibility: The interface eliminates manual paperwork. Students can upload records in seconds; committee members review them with single-click approvals; placement officers filter candidates instantly. The system is operationally feasible and requires zero special training.

Technical Feasibility: Built using proven, robust technologies (Python, Django, React, PostgreSQL) backed by extensive documentation and active developer communities. The system is technically sound.

Economic Feasibility: EduVault utilizes 100% open-source software and is hosted on zero-cost production cloud infrastructure (Vercel, Render, and Neon), resulting in zero software licensing or operational hosting costs.

2.2 User Requirements

Functional Requirements: Secure registration & JWT login; role-based dashboard redirection; document uploading (PDF/JPG/PNG <= 5MB); committee verification & rejection with feedback; placement search with CGPA filtering; dynamic alumni registry; QR code public dossier generation.

Non-Functional Requirements: Sub-300ms API response time; HTTPS encrypted communication; PBKDF2 password hashing with SHA-256; WCAG-compliant responsive design; persistent cloud database integrity.

Custom User Model (`accounts/models.py`):

class User(AbstractUser):
    class Role(models.TextChoices):
        STUDENT = "STUDENT", "Student"
        ALUMNI = "ALUMNI", "Alumni"
        COMMITTEE = "COMMITTEE", "Committee Member"
        PLACEMENT = "PLACEMENT", "Placement Team"

    username = None
    email = models.EmailField(unique=True)
    role = models.CharField(max_length=20, choices=Role.choices, default=Role.STUDENT)
    college = models.CharField(max_length=255, default="MIT-WPU")
    department = models.CharField(max_length=100, default="Computer Science")
    USERNAME_FIELD = "email"
    REQUIRED_FIELDS = ["first_name", "last_name"]

Committee Verification API View (`documents/views.py`):

class VerifyDocumentView(APIView):
    permission_classes = [IsCommittee]

    def post(self, request, pk):
        document = get_object_or_404(Document, pk=pk)
        document.status = Document.Status.VERIFIED
        document.verified_at = timezone.now()
        document.rejection_reason = None
        document.save()
        return Response({"message": "Document verified successfully.", "status": "VERIFIED"})

Frontend Dynamic Media Resolver (`src/api/apiClient.js`):

export const API_BASE_URL = typeof import.meta !== "undefined" && import.meta.env?.VITE_API_URL
  ? import.meta.env.VITE_API_URL.replace(/\/$/, "") : "";

export const getMediaUrl = (url) => {
  if (!url) return "";
  if (url.startsWith("http://") || url.startsWith("https://")) return url;
  const cleanPath = url.startsWith("/") ? url : `/${url}`;
  return `${API_BASE_URL}${cleanPath}`;
};

7. LIMITATIONS

1. Render free-tier cold starts (30-50s spin up after 15 min idle).
2. Ephemeral disk on free container restarts (persistent PostgreSQL, temporary media).
3. Manual committee verification without automated OCR verification.
4. Offline mode not currently available (requires active internet).
