1. INTRODUCTION

Higher education institutions generate immense volumes of academic records, including degree certificates, semester marksheets, co-curricular awards, industrial internship validations, and technical project portfolios. However, the management, storage, verification, and dissemination of these records have historically remained fragmented across manual paper archives, disparate department files, and unverified digital scans. This fragmentation causes severe delays in institutional background checks, fosters academic fraud, burdens placement departments with manual spreadsheet compilation, and isolates graduated alumni from active university mentorship networks.

This chapter describes existing credential management practices and their limitations, introduces the proposed EduVault ecosystem, defines the project scope, outlines hardware and software operational environments, and justifies the technology selections powering the platform.

1.1 EXISTING SYSTEM, PROPOSED SYSTEM AND NEED AND OBJECTIVE OF SYSTEM

1.1.1 Existing System

Academic credential management and campus placement coordination currently depend on four loosely coupled, manual procedures:

(a) Physical Paper Transcripts & Unauthenticated PDF Scans.
Students submit physical photocopies or generic PDF scans of their credentials during semester evaluations and campus placement registrations. These files are not cryptographically tied to an institutional source of truth. Consequently, they are vulnerable to alteration, forged seals, and manipulated marks using basic graphic editing tools.

(b) Manual Administrative Verification Workflows.
Institutions establish academic verification committees to authenticate student credentials. However, verifiers must manually retrieve physical ledger books or query disconnected database spreadsheets. This creates heavy administrative backlogs, with third-party background verification agencies frequently waiting two to four weeks for manual transcript confirmations.

(c) Disconnected Placement & Talent Sourcing.
Training & Placement Officers (TPO) spend countless hours compiling candidate data (CGPA, active backlogs, departmental affiliations, and project links) through Google Forms or spreadsheets. This self-reported data is prone to human error, lacks instant verification, and cannot be dynamically presented to corporate recruiters.

(d) Static Alumni Communication Silos.
Upon graduation, alumni contact records deteriorate into static contact sheets. Universities lack an interactive, database-backed registry where alumni can advertise current company designations, share locations, and declare availability for student mentorship.

1.1.2 Proposed System

EduVault is an end-to-end, enterprise-grade Digital Locker, Academic Credential Verification, and Career Networking Platform. It unites students, verification committees, placement officers, alumni, and external recruiters within a secure, role-governed web application. The platform operates across six core functional tiers:

  1. Authentication & Role Governance Tier: Issues signed JSON Web Tokens (JWT) using Django REST Framework SimpleJWT, routing users automatically into one of four tailored portals: STUDENT, ALUMNI, COMMITTEE, or PLACEMENT.
  2. Student Digital Vault: Enables students to upload, categorize, and track semester marksheets, degree certificates, and achievement files (≤ 5 MB). Uploaded records initiate in a PENDING state.
  3. Academic Committee Verification Pipeline: Provides faculty reviewers with a real-time review queue, in-app full-screen document previewers, instant verification approvals, or rejection feedback mechanisms.
  4. Cryptographic Interview Key & QR Engine: Generates unique UUID-based cryptographic endpoints (e.g. /student/:id and /verify/:id) that render as high-resolution QR codes, enabling corporate recruiters to scan and inspect verified student credentials on mobile devices instantly.
  5. Placement & Corporate Relations Dashboard: Empowers placement teams with aggregate talent metrics (Total Students, Verified Ratio, Average CGPA), instant text search, and multi-tier CGPA threshold pills (≥ 9.0, ≥ 8.0, ≥ 7.5, ≥ 7.0).
  6. Dynamic Alumni Network: An interactive, database-backed directory allowing graduated alumni to publish current roles, employers, geographic locations, and mentorship availability tags.

1.2 SCOPE OF WORK

1.2.1 Functional Scope

The functional scope encompasses all user-facing interactions across the platform:

  • User Registration & Profiling: Account creation with department, college, PRN, phone, and role assignment.
  • JWT Session Security: Token issuance, automated refresh token rotation via Axios interceptors, and logout handling.
  • Student Vault Management: Uploading, previewing, and deleting unverified academic documents.
  • Institutional Committee Queue: Queue sorting, filtering by status/category, full-screen document inspection, single-click verification, and rejection with feedback.
  • Recruitment & Placement Engine: Live talent metrics, candidate search, CGPA threshold filtering, and verified dossier export.
  • Dynamic Alumni Network: Real-time alumni registry with employer, role, location, and mentorship availability filters.
  • Public QR Verification: Tokenized, unauthenticated read-only candidate dossier view for external corporate recruiters.

1.2.2 Technical Scope

  • Backend REST Service: Python 3.11 with Django 6.0 and Django REST Framework, served via Gunicorn WSGI.
  • Persistence: PostgreSQL 16 (Neon Serverless Cloud) managed through Django ORM with ACID-compliant transactions and foreign key cascades.
  • Frontend Application: React 18 with Vite build engine, React Router DOM v6, Tailwind CSS, Lucide React icons, and QRCode.react.
  • Cloud Infrastructure: Vercel for SPA hosting with edge routing; Render for Python WSGI container execution.
  • CORS & Reverse Proxy: Reverse proxy forwarding in Vite for mobile LAN inspection, and open cross-origin production bindings.

1.2.3 Out of Scope and Boundaries

The following are explicitly excluded from the present work:

  1. Dynamic Analysis & OCR: The system stores and displays files; automatic character recognition (OCR) of scanned certificates is excluded from the current release.
  2. Automated Grading: The platform tracks CGPA and marksheets; it does not compute semester examination grades from scratch.
  3. Payment Gateway Integration: Administrative transcript fees are handled externally; online financial transactions are out of scope.
  4. Native Mobile Apps: The system is built as a fully responsive Web App; native compilation for Android APK or iOS IPA is not implemented.

1.4 Description of Technology used

1.4.1 Python 3.11 Runtime Environment

Python 3.11 is used as the primary backend programming language. It delivers substantial execution speed improvements, optimized memory utilization, and precise error tracebacks. Its rich package ecosystem simplifies database communication, file validation, and token cryptography.

1.4.2 Django 6.0 and Django REST Framework (DRF)

Django serves as the backend application framework, offering built-in security mechanisms against Cross-Site Request Forgery (CSRF), SQL Injection, and Cross-Site Scripting (XSS). Django REST Framework provides high-speed serialization, multipart form parsing for uploads, and role permission validation.

1.4.3 SimpleJWT Token Authentication Architecture

JSON Web Tokens (RFC 7519) provide stateless session handling. Upon valid authentication, the server signs an access token (5-minute lifetime) and refresh token (24-hour lifetime). Tokens are transmitted via standard HTTP Authorization: Bearer <token> headers.

1.4.4 React 18 and Vite Tooling Engine

React 18 provides a component-driven declarative UI. Reactive state hooks (useState, useEffect, useMemo, useRef) maintain responsive views without full-page reloads. Vite provides instant development server startup and optimized Rollup production bundling.

1.4.5 Tailwind CSS and Lucide React Visual Components

Tailwind CSS provides a utility-first styling system, enforcing design token consistency across padding, typography, and borders without bulky style files. Lucide React provides intuitive vector SVG icons across all portals.

1.4.6 PostgreSQL 16 and Neon Serverless Persistence

PostgreSQL 16 guarantees relational data integrity. Hosted on Neon Serverless PostgreSQL, it provides auto-scaling compute, scale-to-zero capabilities, and strict ACID transaction safety.

1.4.7 QRCode.react and Cryptographic Token Verification

Client-side QR generation is powered by qrcode.react. Each QR code encodes an authenticated public URL (e.g. https://eduvaul.vercel.app/student/:id), allowing recruiters to scan credentials directly from physical mobile cameras.

1.4.8 Gunicorn WSGI and WhiteNoise Production Static Server

Gunicorn runs as the production Python WSGI HTTP server, handling concurrent client worker processes. WhiteNoise integrates directly into Django's middleware pipeline, serving collected static assets with brotli/gzip compression and immutable caching headers.

2. PROPOSED SYSTEM

EduVault is architected as a decoupled, multi-portal academic credential and placement platform. Each tier maintains a distinct responsibility and communicates with neighboring tiers purely through defined REST API contracts.

The design rests on four core principles:

  • Decoupling: The React client knows only the REST API contract. The Django backend knows nothing about browser DOM rendering. Either can be modified independently.
  • Role Governance: Complete segregation of duties across Students, Alumni, Committee Members, and Placement Teams. Non-student features are inaccessible from student views.
  • Immediate Verifiability: Every verified document carries an immutable timestamp and cryptographic UUID, instantly resolvable via physical QR codes.
  • Zero-Cost Cloud Deployment: Architected specifically to operate on high-availability, free production cloud tiers without institutional capital investment.

Symptom: When students uploaded certificates on the live deployed system, clicking "View File" opened a new tab at https://eduvault-backend1.onrender.com/media/... showing 404 Not Found: The requested resource was not found on this server.

from django.views.static import serve
from django.conf import settings

# Explicitly serve uploaded media files in development and production
urlpatterns += [
    re_path(r"^media/(?P<path>.*)$", serve, {"document_root": settings.MEDIA_ROOT}),
]

from django.contrib.auth.models import AbstractUser, BaseUserManager
from django.db import models

class UserManager(BaseUserManager):
    def create_user(self, email, password=None, **extra_fields):
        if not email:
            raise ValueError("The Email field must be set")
        email = self.normalize_email(email)
        user = self.model(email=email, **extra_fields)
        user.set_password(password)
        user.save(using=self._db)
        return user

    def create_superuser(self, email, password=None, **extra_fields):
        extra_fields.setdefault("is_staff", True)
        extra_fields.setdefault("is_superuser", True)
        return self.create_user(email, password, **extra_fields)

class User(AbstractUser):

import uuid
from django.db import models
from django.conf import settings
from django.core.exceptions import ValidationError

def validate_document_file(value):
    max_size = 5 * 1024 * 1024  # 5 Megabytes
    if value.size > max_size:
        raise ValidationError("File size must not exceed 5 MB.")

    allowed_extensions = [".pdf", ".jpg", ".jpeg", ".png"]
    file_name = value.name.lower()
    if not any(file_name.endswith(ext) for ext in allowed_extensions):
        raise ValidationError("Only PDF, JPG, JPEG and PNG files are allowed.")

class Document(models.Model):
    class Category(models.TextChoices):
        CERTIFICATE = "CERTIFICATE", "Certificate"
        MARKSHEET = "MARKSHEET", "Marksheet"
        INTERNSHIP = "INTERNSHIP", "Internship"
        PROJECT = "PROJECT", "Project"
        ACHIEVEMENT = "ACHIEVEMENT", "Achievement"
        OTHER = "OTHER", "Other"

    class Status(models.TextChoices):
        PENDING = "PENDING", "Pending"
        VERIFIED = "VERIFIED", "Verified"
        REJECTED = "REJECTED", "Rejected"

    user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE, related_name="documents")

    title = models.CharField(max_length=200)

6.3 Committee Verification View (documents/views.py)

File: documents/views.py

from django.utils import timezone
from rest_framework import status
from rest_framework.response import Response
from rest_framework.views import APIView
from .models import Document
from .permissions import IsCommittee

class VerifyDocumentView(APIView):
    permission_classes = [IsCommittee]

    def post(self, request, pk):
        try:
            document = Document.objects.get(pk=pk)
        except Document.DoesNotExist:
            return Response(
                {"error": "Document not found."},
                status=status.HTTP_404_NOT_FOUND
            )

        document.status = Document.Status.VERIFIED
        document.verified_at = timezone.now()
        document.rejection_reason = None
        document.save()

        return Response(
            {
                "message": "Document verified successfully.",
                "verified_at": document.verified_at,
                "status": document.status,
            },
            status=status.HTTP_200_OK,
        )

class RejectDocumentView(APIView):
    permission_classes = [IsCommittee]

    def post(self, request, pk):
        try:
            document = Document.objects.get(pk=pk)
        except Document.DoesNotExist:
            return Response({"error": "Document not found."}, status=status.HTTP_404_NOT_FOUND)

        reason = request.data.get("rejection_reason", "").strip()
        if not reason:
            return Response({"error": "Rejection reason is required."}, status=status.HTTP_400_BAD_REQUEST)

        document.status = Document.Status.REJECTED
        document.rejection_reason = reason
        document.save()

        return Response({"message": "Document rejected.", "rejection_reason": reason})

export const API_BASE_URL =
  typeof import.meta !== "undefined" && import.meta.env?.VITE_API_URL
    ? import.meta.env.VITE_API_URL.replace(/\/$/, "")
    : "";

/**
 * Returns full absolute URL for uploaded media files.
 * In production on Vercel, ensures relative /media paths target the Render backend.
 */
export const getMediaUrl = (url) => {
  if (!url) return "";
  if (url.startsWith("http://") || url.startsWith("https://")) {
    return url;
  }
  const cleanPath = url.startsWith("/") ? url : `/${url}`;
  return `${API_BASE_URL}${cleanPath}`;
};

6.5 QR Code Dynamic Host Resolver (src/utils/qrHelper.js)

File: eduvault-frontend/src/utils/qrHelper.js

// Local IP of this machine on Wi-Fi for phone scanning
export const LOCAL_NETWORK_IP = "192.168.0.106";

/**
 * Returns a URL suitable for scanning by external devices (such as a mobile phone).
 * If the current origin is localhost or 127.0.0.1, it substitutes the local network IP
 * so the phone can access the Vite dev server directly over the local Wi-Fi network.
 */
export const getShareableUrl = (path = "") => {
  if (typeof window === "undefined") return path;

  const isLocalhost =
    window.location.hostname === "localhost" ||
    window.location.hostname === "127.0.0.1";

  const host = isLocalhost
    ? `${LOCAL_NETWORK_IP}:${window.location.port || 5173}`
    : window.location.host;

  const cleanPath = path.startsWith("/") ? path : `/${path}`;
  return `${window.location.protocol}//${host}${cleanPath}`;
};

6.6 Explanation & Architecture Mechanics

Model and ORM Mechanics

Django's ORM abstracts database operations into type-safe Python classes. The User class extends AbstractUser with a custom UserManager, allowing email-based authentication instead of traditional usernames. models.TextChoices provides strongly-typed role and category enumeration, enforcing data consistency at both the Python and SQL layer.

Table 6.1: Architecture design patterns used in EduVault.
Pattern Used For Technical Reason
Single Responsibility Principle API Views vs Serializers vs Models Models handle database schema; serializers handle validation and JSON conversion; views manage HTTP status codes.
Role-Based Access Control (RBAC) DRF Permission Classes (IsCommittee, IsPlacementOrCommittee) Ensures sensitive administrative actions cannot be triggered by student tokens even if the endpoint URL is known.
Stateless Token Authentication SimpleJWT (Access & Refresh Tokens) Eliminates server-side session memory consumption, enabling horizontal container scaling on cloud infrastructure.
Dynamic Host Interpolation qrHelper.js & apiClient.js Allows the same codebase to run seamlessly on localhost, across local mobile Wi-Fi, and in production on Vercel/Render.

Security and Validation Guarantees

All file uploads are validated before saving. validate_document_file() enforces two critical defenses: a 5 MB file size boundary and a strict file extension whitelist (.pdf, .jpg, .jpeg, .png). This prevents server disk exhaustion and neutralizes executable upload vulnerabilities (e.g. PHP or shell scripts).

7. LIMITATIONS

7.1 Cloud Free-Tier Spin-Down Boundary

EduVault is deployed on Render's free container tier. As part of Render's resource allocation policy, web services spin down into sleep mode after 15 minutes of inactivity. When a user accesses the platform after dormancy, the container requires 30 to 50 seconds to initialize. Once awake, response latency drops below 200 ms.

Ephemeral Storage Stateless container filesystem on Render Uploaded files in media/ reset upon full container rebuilds PostgreSQL database is permanently hosted on Neon; media serving is enabled.
Manual Committee Review Human faculty verification required Verification depends on committee review availability Status tracking (PENDING, VERIFIED, REJECTED) with instant student feedback.

7.2 Heuristic False Positives & OCR Boundary

The system stores and renders files as authentic digital assets. However, automated Optical Character Recognition (OCR) against institutional ledger databases is not integrated in the current release. Verification authenticity relies on human committee approval rather than algorithmic pixel matching.
